Bangers — Comic title font — A bold display font that looks like classic American comic book lettering. Used for chapter titles, the DrukShift logo on the splash screen, and all large headings throughout the webtoon.

Comic Neue — Speech bubble font — A clean handwritten-style font designed specifically for comics. Used inside all speech bubbles for Deki, Tenzin, Tourist and Narrator text to give an authentic comic feel.

Noto Serif — Narrative font — A classic serif font used for narrator captions and pull quotes. The serif style gives a literary, storytelling quality to the narrator voice.

Outfit — UI font — The same clean sans-serif used across all DrukShift pages. Used for labels, page numbers, and interface text.

Four different fonts — Typography system — Using different fonts for different purposes (titles, speech, narration, UI) is a key technique in comics and webtoons. Each font has its own personality and role.

Four bubble types — Character voices — Regular white bubble for Deki and others, shout bubble (orange) for excited speech, thought bubble (pale blue rounded) for internal thoughts, info bubble (navy) for narrator text.

bub-dl, bub-dr, bub-ul, bub-ur — Tail direction — dl = down-left (tail points to character below-left), dr = down-right, ul = up-left, ur = up-right. These are combined with bub to position the speech tail pointing toward the correct character.

Inline style positioning — Manual placement — Each bubble is positioned using inline top/bottom/left/right values. This gives full control over where each bubble appears within each specific panel since every panel has a different composition.

max-width on bubbles — Text wrapping — Limits bubble width so text wraps rather than stretching across the panel. Typical comic bubbles are narrow and tall rather than wide.

<em> for dialogue — Italic speech — Deki's dialogue is wrapped in em tags making it italic. This differentiates her actual spoken words from character labels like DEKI: in the bubble.

.bub-thought::after,

  background: #f4a261;
  border-color: #c0603a;
  color: #08192d;
  border-radius: 4px;
  transform: rotate(-1deg);
}

Speech bubble tail technique — CSS border trick — The tail is created using two pseudo-elements (::after and ::before). A border with all sides transparent except one creates a CSS triangle. The ::after creates a slightly larger black triangle for the border, and ::before creates a slightly smaller white triangle on top creating the tail with a border outline.

::after bottom:-20px — Position below bubble — Placing the triangle 20px below the bubble bottom makes it appear as a tail pointing downward from the bubble.

border:10px solid transparent border-top-color:#111 — Triangle creation — Setting all borders transparent except the top creates a downward-pointing triangle. The top border colour is the triangle colour. The 10px defines the triangle size.

bub-thought border-radius:50px — Pill shaped bubble — Very large border-radius on all corners creates a rounded pill shape. display:none on both pseudo-elements hides the tail since thought bubbles float without a pointed tail.

bub-shout transform:rotate(-1deg) — Slight tilt — A -1 degree rotation makes shout bubbles appear slightly askew like handwritten text giving urgency and energy to the speech.

JavaScript Start Comic
drukshift_story.html — JavaScript — startComic()
var cur = 1, total = 10;

function startComic() {
  var sp = document.getElementById('splash');
  sp.style.opacity = '0';           // fade out

  setTimeout(function() {
    sp.style.display = 'none';      // remove from layout
    document.getElementById('comic').style.display = 'block';
    document.getElementById('cnav').style.display  = 'flex';
    upd();
  }, 700);                          // wait for fade
}

cur = 1 and total = 10 — State variables — cur tracks which page is currently showing. total is the fixed total of 10 pages. Both are declared outside functions so all functions can access them.

sp.style.opacity = '0' — Start fade — Sets opacity to 0 triggering the CSS transition:opacity 0.8s on the splash element making it fade out smoothly.

setTimeout 700ms — Wait for fade — Waits 700ms (slightly less than the 0.8s fade) before hiding the splash and showing the comic. The fade starts, then just before it finishes the element is hidden and comic appears.

display:none after fade — Remove from layout — Setting display:none after the fade completely removes the splash from the page layout. Just opacity:0 would still take up space — display:none removes it entirely.

cnav display:flex — Show navigation — The navigation starts display:none. flex is used (not block) because the nav uses flexbox to align its children in a row.

JavaScript Page Navigation
drukshift_story.html — JavaScript — goTo(), next(), prev()
function goTo(n) {
  // Remove active from current page
  document.getElementById('p' + cur).classList.remove('active');

  // Update current page number
  cur = n;

  // Add active to new page — triggers pageIn animation
  document.getElementById('p' + cur).classList.add('active');

  // Scroll to top of page
  window.scrollTo({ top:0, behavior:'smooth' });

  // Update nav buttons and progress bar
  upd();
}

function next() { if (cur < total) goTo(cur + 1); }
function prev() { if (cur > 1)    goTo(cur - 1); }

classList.remove('active') — Hide current page — Removes the active class from the current page. In CSS wt-page without active has display:none making it invisible.

cur = n — Update state — Updates the current page variable before adding active to the new page. This keeps the state accurate for the upd() function.

classList.add('active') — Show new page — Adding active to the new page gives it display:block in CSS and triggers the pageIn animation making it slide and fade in.

scrollTo top:0 smooth — Scroll reset — Scrolls back to the top of the page on each navigation. Important because some pages are very long and the reader would otherwise land in the middle of a new page.

next and prev guard conditions — Boundary check — if (cur < total) prevents going past the last page. if (cur > 1) prevents going before the first page. These guard clauses avoid trying to show non-existent pages.

JavaScript Progress Bar Update
drukshift_story.html — JavaScript — upd()
function upd() {
  // Disable prev button on page 1
  document.getElementById('prevBtn').disabled = (cur === 1);

  // Disable next button on last page
  document.getElementById('nextBtn').disabled = (cur === total);

  // Update page indicator text
  document.getElementById('ind').textContent = cur + ' / ' + total;

  // Update reading progress bar width
  // Page 1 = 0%, Page 10 = 100%
  document.getElementById('prog').style.width =
    ((cur - 1) / (total - 1) * 100) + '%';
}

disabled = (cur === 1) — Boolean assignment — cur === 1 evaluates to true or false. Assigning that to disabled sets the button as disabled on page 1 and enabled on all other pages. Clean one-liner.

Page indicator text — String concatenation — cur + ' / ' + total builds the string e.g. "3 / 10". textContent sets the text inside the indicator div.

Progress formula (cur-1)/(total-1)*100 — Percentage calculation — Page 1: (1-1)/(10-1)*100 = 0%. Page 10: (10-1)/(10-1)*100 = 100%. Subtracting 1 from both ensures page 1 starts at 0% and page 10 ends at 100%.

JavaScript Keyboard Navigation
drukshift_story.html — JavaScript — Keyboard Events
document.addEventListener('keydown', function(e) {
  if (e.key === 'ArrowRight' || e.key === ' ') next();
  if (e.key === 'ArrowLeft')  prev();
});

keydown event — Keyboard listener — Fires whenever any key is pressed while the page has focus. e.key contains the name of the pressed key as a string.

ArrowRight and Space — Next page keys — Both right arrow and spacebar go to the next page. Space is the natural reading key — used to scroll down in browsers. Here it advances the page instead.

ArrowLeft — Previous page key — Left arrow goes back. This makes the webtoon feel like flipping pages in a real comic book or ebook reader.

Result: Readers can navigate the webtoon using keyboard arrows or spacebar without needing to click buttons. This makes it accessible and comfortable for desktop users.
JavaScript Touch Swipe Navigation
drukshift_story.html — JavaScript — Touch Swipe
var tx = 0;

// Record where finger first touched the screen
document.addEventListener('touchstart', function(e) {
  tx = e.touches[0].clientX;
}, { passive: true });

// When finger lifts calculate swipe direction
document.addEventListener('touchend', function(e) {
  var d = tx - e.changedTouches[0].clientX;

  if (Math.abs(d) > 50) {   // only count as swipe if moved 50px
    if (d > 0) next();      // swiped left  → next page
    else       prev();      // swiped right → previous page
  }
});

tx variable — Touch start X — Stores the X coordinate (horizontal position) where the finger first touched the screen.

e.touches[0].clientX — Touch position — touches is an array of all active touch points. [0] is the first finger. clientX is the horizontal position in pixels from the left edge of the screen.

e.changedTouches[0].clientX — End position — changedTouches contains touch points that changed in this event. At touchend this is where the finger lifted.

d = tx - endX — Swipe distance — Positive d means the finger moved left (tx was further right than end position) = swiped left = next page. Negative d means swiped right = previous page.

Math.abs(d) > 50 — Minimum swipe — Only counts as a swipe if the finger moved more than 50 pixels. Prevents accidental page turns from tiny finger movements or taps.

passive:true — Performance hint — Tells the browser this touchstart listener will not call preventDefault. Allows the browser to optimise scrolling performance.

Result: On mobile phones and tablets readers can swipe left to go forward and swipe right to go back — exactly like a real comic app or ebook reader.

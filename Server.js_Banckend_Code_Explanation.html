Node.js Imports and App Setup
server.js — Imports and Setup
const express    = require("express");
const mongoose   = require("mongoose");

require() — Node.js import — Node.js way of importing external packages. Like import in Python. Each package must be installed using npm install before it can be required.

express — Web framework — Express is the most popular Node.js framework for building web servers and APIs. It makes it easy to define routes and handle HTTP requests and responses.

mongoose — MongoDB library — Mongoose is an ODM (Object Data Modelling) library for MongoDB. It lets you define schemas, create models, and interact with MongoDB using JavaScript objects instead of raw database queries.

nodemailer — Email library — Nodemailer is a Node.js library for sending emails. Used here to send OTP verification codes to users via Gmail.

const app = express() — App instance — Creates the Express application instance. All routes, middleware and settings are attached to this app object. app.listen() at the bottom starts the server.

Node.js CORS Middleware
server.js — CORS Middleware
app.use((req, res, next) => {
    res.header("Access-Control-Allow-Origin",  "*");
    res.header("Access-Control-Allow-Methods", "GET, POST, OPTIONS");
    res.header("Access-Control-Allow-Headers", "Content-Type");
    if (req.method === "OPTIONS") {
        return res.sendStatus(200);
    }
    next();
});

app.use(express.json());

app.use() — Middleware registration — Registers a middleware function that runs on every request before it reaches the route handlers. Middleware can modify the request or response or pass control to the next function.

CORS — Cross-Origin Resource Sharing — Security policy — By default browsers block requests from one domain to another for security. Our frontend is on github.io but the backend is on onrender.com — different domains. CORS headers tell the browser this is allowed.

Access-Control-Allow-Origin: * — Allow all origins — The * means any website can make requests to this backend. In production a specific domain like kinzang7066.github.io would be used for security.

OPTIONS method check — Preflight request — Before making a real request browsers first send an OPTIONS preflight request to check if CORS is allowed. This code immediately responds with 200 OK to those preflight requests.

next() — Pass to next middleware — Tells Express to continue to the next middleware or route handler. Without calling next() the request would hang and never get a response.

express.json() — JSON parser — Built-in Express middleware that parses incoming requests with JSON bodies. Without this req.body would be undefined when the frontend sends JSON data.

mongoose.connect() — Database connection — Establishes a connection to the MongoDB Atlas cloud database. Returns a Promise — .then runs if successful, .catch runs if it fails.

Connection string format — MongoDB URI — mongodb+srv:// is the protocol for MongoDB Atlas cloud. admin is the username, Oracle2025 is the password, cluster0.4mebvxb.mongodb.net is the cluster address.

.then() and .catch() — Promise handling — These handle the result of the async connection. .then runs the success callback when connected. .catch runs the error callback if connection fails.

console.log() — Server logging — Prints messages to the server terminal. Useful for debugging — when the server starts you can see in the Render logs whether MongoDB connected successfully.

Security note: The connection string contains the database password. In a production application this would be stored in an environment variable (process.env.MONGO_URI) not hardcoded in the file.

require('./models/User') — Local file import — The ./ means import from a local folder. The models folder contains Mongoose schema definitions for the database collections.

User model — Users collection — Represents the users MongoDB collection. Each document stores a user's name, email and when they registered. The email field is unique — one user per email address.

QuizResult model — Quiz results collection — Represents the quizresults MongoDB collection. Each document stores the userId (linking to the User), their score percentage, their 10 individual answers as an array, and the timestamp.

userId: ObjectId reference — Database relationship — Links each quiz result to a user. Like a foreign key in SQL databases. This allows fetching all quiz results for a specific user.

answers: [Number] — Array field — Stores all 10 quiz answers as an array of numbers. answers[0] is the Q1 answer, answers[9] is Q10. This allows the admin dashboard to calculate domain averages.

nodemailer.createTransport() — Email sender setup — Creates an email transport object configured to send emails through Gmail. This transporter is reused every time an email needs to be sent.

Node.js OTP Store
server.js — In-Memory OTP Storage
// { email: { otp: '1234', expires: timestamp } }
var otpStore = {};

// Example of what it looks like when populated:
// {
//   'user@example.com': {
//     otp: '4729',
//     expires: 1715432800000  // Unix timestamp
//   }
// }

otpStore object — In-memory store — A plain JavaScript object used as a temporary key-value store. The email address is the key and the OTP data is the value.

In-memory storage — RAM storage — Stored in the server's RAM not in MongoDB. This means OTPs are lost if the server restarts. Acceptable for short-lived OTPs but not for persistent data.

expires: Date.now() + 10 * 60 * 1000 — Expiry timestamp — Date.now() returns current time in milliseconds. Adding 10 * 60 * 1000 (10 minutes in milliseconds) gives the expiry time. When verifying the OTP Date.now() is compared to this value.

delete otpStore[email] — Cleanup — After the OTP is verified or expires it is deleted from the store. This prevents old OTPs from being reused and keeps the store small.

Node.js POST /api/send-otp
server.js — Send OTP Route
POST/api/send-otp

app.post('/api/send-otp', async (req, res) => {
    try {
        const { email } = req.body;
        if (!email) return res.status(400).json({ error: 'Email is required' });

        // Generate 4-digit OTP
        var otp = Math.floor(1000 + Math.random() * 9000).toString();

        // Store with 10 minute expiry
        otpStore[email] = {
            otp:     otp,
            expires: Date.now() + 10 * 60 * 1000
        };

        // Send email using nodemailer
        await transporter.sendMail({
            from:    '"DrukShift 🇧🇹" <chodenkinzang829@gmail.com>',
            to:      email,
            subject: 'Your DrukShift Quiz Verification Code',
            html:    `<div>...styled HTML with ${otp}...</div>`
        });

        res.json({ success: true, message: 'OTP sent successfully' });

    } catch (err) {
        res.status(500).json({ error: 'Failed to send OTP.' });
    }
});

app.post() — POST route — Handles HTTP POST requests. POST is used when sending data to the server (as opposed to GET which just retrieves data).

async (req, res) — Async route handler — The async keyword allows using await inside the function. Needed because sending an email is an asynchronous operation that takes time.

const { email } = req.body — Destructuring — Extracts the email property from req.body. Same as writing const email = req.body.email.

res.status(400).json() — Error response — 400 is the HTTP status code for Bad Request. Returned when required data is missing. The .json() sends the error message as JSON.

Math.floor(1000 + Math.random() * 9000) — 4-digit OTP — Math.random() gives 0-1, multiplied by 9000 gives 0-9000, adding 1000 gives 1000-10000, Math.floor rounds down. Result is always a 4-digit number between 1000 and 9999.

Template literal with ${otp} — String interpolation — Backtick strings allow embedding variables using ${} syntax. The OTP number is inserted directly into the HTML email body.

try/catch block — Error handling — Wraps the async operations. If anything fails — network error, Gmail error etc — the catch block runs and sends a 500 Internal Server Error response instead of crashing.

Node.js POST /api/verify-otp
server.js — Verify OTP Route
POST/api/verify-otp

app.post('/api/verify-otp', (req, res) => {
    try {
        const { email, otp } = req.body;
        if (!email || !otp) return res.status(400).json({ error: 'Email and OTP required' });

        var stored = otpStore[email];

        // Check OTP exists
        if (!stored) {
            return res.status(400).json({ error: 'No OTP found. Please request a new one.' });
        }

        // Check not expired
        if (Date.now() > stored.expires) {
            delete otpStore[email];
            return res.status(400).json({ error: 'OTP has expired. Please request a new one.' });
        }

        // Check OTP matches
        if (stored.otp !== otp.toString()) {
            return res.status(400).json({ error: 'Incorrect code. Please try again.' });
        }

        // All checks passed — clear OTP and verify
        delete otpStore[email];
        res.json({ success: true, message: 'Email verified successfully!' });

    } catch (err) {
        res.status(500).json({ error: err.message });
    }
});

Three validation checks — Guard clauses — Each check uses an early return if something is wrong. This avoids deeply nested if/else and makes the code easy to read.

!stored check — OTP existence — If no OTP was stored for this email the user never requested one or it was already used. Returns an error asking them to request a new one.

Date.now() > stored.expires — Expiry check — Compares current time to the stored expiry timestamp. If current time is past the expiry the OTP has expired. The expired OTP is deleted to keep the store clean.

stored.otp !== otp.toString() — Code comparison — Compares the stored OTP string with what the user sent. .toString() ensures both are strings for proper comparison — the user might send a number but the stored value is always a string.

delete otpStore[email] — One-time use — Deletes the OTP after successful verification. This ensures OTPs can only be used once — reusing the same code would fail because it is deleted from the store.

Node.js POST /api/quiz
server.js — Save Quiz Result
POST/api/quiz

app.post('/api/quiz', async (req, res) => {
    try {
        const { name, email, score, answers } = req.body;

        // Find existing user or create new one
        let user = await User.findOne({ email });
        if (!user) {
            user = await User.create({ name, email });
        }

        // Save quiz result linked to user
        const result = await QuizResult.create({
            userId:  user._id,
            score:   score,
            answers: answers
        });

        res.json({ success: true, userId: user._id, result });

    } catch (err) {
        res.status(500).json({ error: err.message });
    }
});

const { name, email, score, answers } = req.body — Destructuring — Extracts all four fields from the request body that the frontend sends after quiz completion.

User.findOne({ email }) — Database query — Searches MongoDB for a user with the matching email address. Returns the user document if found or null if not found.

Find or create pattern — Upsert logic — If a user already exists (returning quiz taker) use their existing record. If not found create a new user. This means the same person can take the quiz multiple times and all results are linked to one user account.

await User.create() — Create document — Creates and saves a new document in the users MongoDB collection. Returns the newly created document including its auto-generated _id.

userId: user._id — Linking records — Stores the user's MongoDB _id in the quiz result. This creates the relationship between the users and quizresults collections allowing quiz history to be fetched per user.

res.json({ success: true, userId, result }) — Success response — Returns the saved data back to the frontend. The frontend uses this to confirm the save was successful.

Node.js GET /api/quiz/:email
server.js — Get Quiz History
GET/api/quiz/:email

app.get('/api/quiz/:email', async (req, res) => {
    try {
        // Find user by email from URL parameter
        const user = await User.findOne({ email: req.params.email });

        // If user not found return empty history
        if (!user) return res.json({ history: [] });

        // Get all their quiz results sorted newest first
        const history = await QuizResult.find({ userId: user._id })
                                        .sort({ takenAt: -1 });

        res.json({ user, history });

    } catch (err) {
        res.status(500).json({ error: err.message });
    }
});

:email in route path — URL parameter — The colon makes email a dynamic parameter. When the frontend requests /api/quiz/user@example.com the value user@example.com is available as req.params.email.

req.params.email — URL parameter access — Express automatically parses URL parameters and makes them available on req.params. The name matches whatever came after the colon in the route definition.

QuizResult.find({ userId: user._id }) — Filter query — Finds all quiz results where the userId field matches the user's _id. Returns all attempts by that user.

.sort({ takenAt: -1 }) — Descending sort — -1 means descending order (newest first). The most recent quiz attempt appears first in the array.

Used for history comparison — Progress tracking — The frontend calls this after saving a new result to check if the user has previous attempts and show their improvement or decline compared to last time.

Node.js GET /api/admin/users
server.js — Admin Get All Users
GET/api/admin/users

app.get('/api/admin/users', async (req, res) => {
    try {
        const users = await User.find({}).sort({ createdAt: -1 });
        res.json({ users });
    } catch (err) {
        res.status(500).json({ error: err.message });
    }
});

User.find({}) — Find all — The empty {} object means no filter — return all documents in the users collection. Same as SELECT * FROM users in SQL.

.sort({ createdAt: -1 }) — Newest first — Sorts users by creation date descending. Newest registered users appear first in the admin dashboard table.

res.json({ users }) — JSON response — Wraps the users array in an object. The admin dashboard JavaScript accesses it as data.users in the fetch response handler.

No authentication: This route has no password protection — anyone who knows the URL can access all user data. For a production system this would require an authentication token. For this internship project the admin page has its own password check on the frontend.

server.js — Admin Get All Results

app.get('/api/admin/results', async (req, res) => {
    try {
        const results = await QuizResult.find({}).sort({ takenAt: -1 });

QuizResult.find({}) — All results — Returns every quiz result document in the database with no filtering. Includes score, answers array, userId and timestamp for every attempt.

Used by admin dashboard and live counter — Dual purpose — This endpoint is used in two places. The admin dashboard uses it to render all charts and the table. The main website hero uses it to show the live quiz count by reading data.results.length.

answers array in results — Domain analysis — Each result includes the full answers array. The admin dashboard uses this to calculate average scores per domain by reading answers[0] through answers[9] across all results.

Node.js Start Server

const PORT = 5000;
app.listen(PORT, () => {

PORT = 5000 — Port number — Port 5000 is used when running locally. When deployed on Render the platform overrides this with its own port via the PORT environment variable.

app.listen() — Start server — This is the last line that actually starts the server and makes it listen for incoming HTTP requests. Everything above just sets up the configuration — this line activates it.

Callback function — Ready confirmation — The arrow function runs once when the server successfully starts. The console.log message appears in the terminal (or Render logs) confirming the server is ready to accept requests.

Template literal with PORT — Dynamic message — The backtick string with ${PORT} inserts the actual port number into the message. Shows "Server running on port 5000 🚀" in the terminal.

01

DOCTYPE and Head Section

Lines 1 to 8 — Setup and imports

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Cryptocurrency Readiness in Bhutan | DrukShift</title>
  <link href="https://fonts.googleapis.com/css2?family=Outfit..." rel="stylesheet">
  <script src="https://public.tableau.com/javascripts/api/tableau.embedding..."></script>

Line 1 — DOCTYPE: Tells the browser this is a modern HTML5 document. Without this the browser would use old rendering rules and the website would look broken.

Line 2 — html lang="en": Opens the HTML document and sets the language to English. This helps screen readers and search engines understand the content.

Line 3 — meta charset UTF-8: Sets the character encoding. UTF-8 supports all characters including Bhutanese text, emojis, and special symbols. Without this, characters would display as question marks.

Line 4 — viewport meta tag: This is the most important line for mobile responsiveness. It tells the browser to match the screen width of the device. Without this line, the website would appear tiny on phones and tablets.

Line 5 — title tag: Sets the text that appears in the browser tab and in Google search results.

Line 6 — Google Fonts link: Imports the Outfit and Cormorant Garamond fonts from Google's servers. Outfit is used for body text and Cormorant Garamond is used for headings.

Line 7 — Tableau script: Loads the Tableau JavaScript library which allows Tableau visualizations to be embedded on the page.

scroll-behavior smooth: Makes the page scroll smoothly when you click a navigation link instead of jumping instantly.

overflow-x hidden: Prevents horizontal scrolling on the page which can happen when animations move elements slightly off screen.

Breadcrumb Navigation

Added to fix the "too much scrolling" feedback

<div id="breadcrumb">
  <div class="bc-item">
    <button class="bc-link active" onclick="bcGo('home')">🏠 Home</button>
    <span class="bc-sep">›</span>
  </div>
  <!-- ... more sections ... -->
</div>

// JavaScript that powers it
function bcGo(id) {
  var el = document.getElementById(id);
  var offset = 100;
  var top = el.getBoundingClientRect().top + window.scrollY - offset;
  window.scrollTo({ top: top, behavior: 'smooth' });
}

function bcUpdate() {
  // Detects which section is on screen and highlights it
  var scrollY = window.scrollY + 120;
  bcSections.forEach(function(id) {
    var el = document.getElementById(id);
    if (el && el.offsetTop <= scrollY) current = id;
  });
}

What it does: The breadcrumb bar appears just below the main nav when you scroll past the hero section. It shows all sections as clickable buttons. When you click one it smoothly scrolls to that section.

bcGo function: Gets the element by its ID, calculates its position on the page using getBoundingClientRect, subtracts an offset of 100px so the section does not hide behind the sticky nav, then scrolls to that position smoothly.

bcUpdate function: Runs every time the user scrolls. It checks which section is currently on screen by comparing the scroll position to each section's position. The current section gets the active class which highlights it in orange.

Why I added this: My supervisor gave feedback that the website had too much scrolling. The breadcrumb solves this by letting users jump directly to any section in one click.

About and Stats Section

<section class="stats-section">

    <div class="stat-lbl">Adults Surveyed</div>

// JavaScript counter animation
function animateCounter(el) {
  var target = parseFloat(el.getAttribute('data-target'));
  var duration = 1500;
  var start = performance.now();
  function update(time) {
    var progress = Math.min((time - start) / duration, 1);
    el.textContent = Math.floor(progress * target);
    if (progress < 1) requestAnimationFrame(update);
    else el.textContent = target;
  }
  requestAnimationFrame(update);
}

data-target attribute: Each stat card stores its final number in a custom HTML attribute called data-target. The JavaScript reads this value and counts up to it.

IntersectionObserver: The counter only starts when the stats section scrolls into view. An IntersectionObserver watches each stat element and calls animateCounter when it becomes visible on screen.

requestAnimationFrame: This is a browser function that runs a callback on every animation frame — about 60 times per second. It is used instead of setInterval because it is smoother and pauses automatically when the user switches tabs.

Readiness Section

Animated progress bars by age group

<div class="readiness-bar-row">
  <div class="readiness-bar-label">25–34 Age Group</div>
  <div class="readiness-bar-track">
    <div class="readiness-bar-fill"
         data-width="86"
         style="width:0%;background:#2a9d8f">
    </div>
  </div>
  <span>86%</span>
</div>

// JavaScript that animates the bars
var observer = new IntersectionObserver(function(entries) {
  entries.forEach(function(entry) {
    if (entry.isIntersecting) {
      var fill = entry.target;
      fill.style.width = fill.getAttribute('data-width') + '%';
    }
  });
});

data-width attribute: Each bar's target width is stored in a custom data-width attribute. The bar starts at width 0% in the inline style. When it scrolls into view JavaScript reads the data-width and sets the width to that value.

CSS transition: The bar fill element has transition width 0.8s ease in CSS. This means when the width changes from 0% to 86% it animates smoothly over 0.8 seconds instead of snapping instantly.

IntersectionObserver: This is a modern browser API that watches elements and fires a callback when they enter or exit the visible area of the screen. It is much better than using scroll events because it does not run on every single scroll movement.

// Quiz questions array
var qQuestions = [
  { q: "How familiar are you with cryptocurrency?", domain: "Knowledge" },
  { q: "How confident using a crypto wallet?", domain: "Technical Skill" },
  // ... 10 questions total
];
var qAnswers = [];
var qCurrent = 0;

function qRender() {
  var q = qQuestions[qCurrent];
  document.getElementById('qText').textContent = q.q;
  // Build 10 numbered buttons dynamically
  var html = '';
  for (var i = 1; i <= 10; i++) {
    html += '<button class="q-likert-btn" onclick="qSelect(' + i + ')">' + i + '</button>';
  }
  document.getElementById('qButtons').innerHTML = html;
}

Quiz structure: The quiz card is a single HTML element that gets updated dynamically by JavaScript. Instead of having 10 separate HTML sections for each question I use one card and change its content using JavaScript.

qAnswers array: Every time a user clicks a number button their answer is pushed into the qAnswers array. After all 10 questions qAnswers holds 10 numbers like [7,5,8,6,3,9,7,4,8,6].

qRender function: This function updates the quiz card to show the current question. It reads from qQuestions array at position qCurrent and sets the question text. It also builds the 10 numbered buttons using a for loop and innerHTML.

Progress bar: The progress fill width is updated on every question — (qCurrent / 10) * 100 percent — so it grows as the user moves through the quiz.

Personalised results: When all 10 questions are answered the qShowResults function calculates the total score, compares it to the 80% Bhutan average, assigns a badge, and generates a personalised solution for each question where the user scored low. For example if Q5 is 3 out of 10 the results show "Because you rated your Personal Readiness as 3/10, your next step is..."

function switchTab(tab) {
  document.querySelectorAll('.res-tab').forEach(function(t) {
    t.classList.remove('active');
  });
  document.querySelectorAll('.res-content').forEach(function(c) {
    c.classList.remove('active');
  });
  document.getElementById('tab-' + tab).classList.add('active');
}

Tab system: Two tabs — For Individuals and For Small Businesses. Clicking a tab calls switchTab which removes active from all tabs and content divs then adds active to the clicked tab and its matching content div.

res-content display: In CSS the res-content class has display none. The res-content.active class has display block. So only the active tab's content is visible at any time.

Resource cards: Each card has a type — video, guide, or link — which determines its colour scheme using CSS classes. All links open in a new tab using target blank.

Main JavaScript Block

All the interactive functionality

// ── HERO SLIDESHOW ──
var slides = document.querySelectorAll('.hero-slide');
var current = 0;
function nextSlide() {
  slides[current].classList.remove('active');
  current = (current + 1) % slides.length;
  slides[current].classList.add('active');
}
var slideshowInterval = setInterval(nextSlide, 1500);

// ── DARK/LIGHT MODE ──
function toggleDark() {
  document.body.classList.toggle('dark');
  localStorage.setItem('theme',
    document.body.classList.contains('dark') ? 'dark' : 'light'
  );
}

// ── LIVE QUIZ COUNTER ──
fetch('https://drukshift-vakend.onrender.com/api/admin/results')
  .then(function(r) { return r.json(); })
  .then(function(data) {
    document.getElementById('liveCount').textContent = data.length;
  });

// ── SCROLL REVEAL ──
var revealObserver = new IntersectionObserver(function(entries) {
  entries.forEach(function(entry) {
    if (entry.isIntersecting) {
      entry.target.classList.add('visible');
    }
  });
}, { threshold: 0.1 });
document.querySelectorAll('.reveal').forEach(function(el) {
  revealObserver.observe(el);
});

Slideshow: setInterval calls nextSlide every 1500 milliseconds — 1.5 seconds. nextSlide removes the active class from the current slide, increases the current index by 1, and adds active to the new slide. The modulo operator % makes it loop back to 0 after the last slide.

Dark/Light mode: toggleDark adds or removes the dark class on the body element. All dark mode CSS rules are written under body.dark in the stylesheet. localStorage.setItem saves the user's preference so it is remembered when they come back to the website.

Live quiz counter: The fetch function makes a GET request to the backend API. The API returns an array of all quiz results from MongoDB. The length of the array is the total number of people who have taken the quiz. This number is displayed in the hero section.

Scroll reveal: An IntersectionObserver watches every element with the reveal class. When an element becomes 10% visible — threshold 0.1 — it adds the visible class. In CSS the visible class sets opacity to 1 and transform to none creating the fade-in animation.

// ── GAME 1: CRYPTO QUIZ BLITZ ──
function mgInitBlitz() {
  mgBState = {
    qs: mgShuffle(mgBlitzQs).slice(0, 10),
    cur: 0, score: 0, timeLeft: 30
  };
  mgBlitzRender();
  mgBlitzTimer();
}

// ── GAME 2: SCAM SPOTTER ──
function mgScamAns(ans) {
  var m = mgSState.msgs[mgSState.cur];
  var correct = (ans === 'scam') === m.isScam;
  if (correct) mgSState.score++;
}

// ── GAME 3: MEMORY MATCH ──
function mgMemFlip(idx) {
  mgMState.flipped.push(idx);
  if (mgMState.flipped.length === 2) {
    var c1 = mgMState.cards[mgMState.flipped[0]];
    var c2 = mgMState.cards[mgMState.flipped[1]];
    if (c1.pairId === c2.pairId) {
      mgMState.matched.push(c1.pairId); // Match found!
    }
  }
}

Why addEventListener instead of onclick: The game cards use addEventListener attached after the page fully loads using window.addEventListener load. This was the fix for the mgStart error shown in the console. If onclick was used directly in HTML the function would be called before the JavaScript was ready.

Game 1 — Crypto Quiz Blitz: 10 true/false questions are randomly shuffled using mgShuffle which is a Fisher-Yates shuffle algorithm. A 30 second timer runs using setInterval. When time runs out or all questions are answered mgShowResult is called.

Game 2 — Scam Spotter: 8 real and fake messages are shown one by one. Each has isScam true or false. The mgScamAns function compares the user's choice with the correct answer and increments the score. Each message has a 10 second timer.

Game 3 — Memory Match: Cards are stored in an array with pairId values. When two cards are flipped the function checks if their pairId matches. If yes they stay face up and are added to the matched array. If no they flip back after 800 milliseconds using setTimeout.

XP system: All three games call mgAddXP after they finish. This adds points to mgXP which is stored in localStorage. The XP bar in the sidebar is updated using mgUpdateXP which calculates the fill percentage and sets the bar width.

Key design decision: All three games are embedded directly inside index.html rather than in separate files or iframes. This means they load instantly with the page and can access the same XP system and gamification variables as the rest of the website.
